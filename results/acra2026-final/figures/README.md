# Figures — ACRA 2026 final results

Generated by `python scripts/plot_outcomes.py` from the repository root. Each
figure exists as **PDF** (vector; include this one in LaTeX) and **PNG** (for
viewing). Tables are in [`../tables/`](../tables/) (`python scripts/build_result_tables.py`).

Every figure has a short title saying what is compared, and a subtitle giving
the key numbers (computed from the data) plus how to read it. Each figure uses
one result set; the horizon sweep's "no prediction (0 ms)" point is, by design,
the policy comparison's event @ 20 ms arm.

"Full-path recalculation" is the `event_route` policy (result set `event-route-ablation`): rebuild whenever any remaining route segment is blocked, after Costa and Tonidandel (RoboCup 2023, LNAI 14140, 2024).

| Figure | Result set | What is compared | How to read it |
|---|---|---|---|
| `oneshot_planning_time_and_route_length` | One-Shot Planning Validation | Planning time vs route length, by planner | Cumulative curves; further left = faster (left panel) or shorter (right). Only requests whose straight line was blocked |
| `policy_outcomes` | Policy Comparison | Run outcomes: cycle vs event trigger | Each bar = 200 runs: finished clean (blue), came within 30 mm (yellow), touched something (red), did not finish (grey) |
| `policy_collision_free` | Policy Comparison | Collision-free finishes: cycle vs event trigger | % of 200 runs where every robot reached its goal without touching anything |
| `policy_compute_vs_safety` | Policy Comparison | Replanning effort vs contact rate | x = replans per run (log), y = % of finished runs that touched something; colour = planner, square/circle = cycle/event, filled/hollow = 20/100 ms |
| `policy_replan_latency_20ms` | Policy Comparison | Rebuild time: cycle vs event at 20 ms checks | Share of successful rebuilds finished within x ms; line at 100 ms = replan limit; counts in the corner |
| `policy_replan_latency_100ms` | Policy Comparison | Same at 100 ms checks | As above |
| `policy_route_lifetime` | Policy Comparison | Route lifetime: cycle vs event trigger | Average time a route is followed before replacement |
| `horizon_outcomes` | Prediction Horizon Sweep | Run outcomes vs prediction horizon | Same bars as `policy_outcomes`, horizons 0 (none), 20, 50, 100 ms |
| `horizon_trends` | Prediction Horizon Sweep | Safety and replanning vs horizon | 2×2: clean finishes, touched something, did not finish, replans per run |
| `table_rebuild_latency` | Policy Comparison | Cycle vs event rebuild time for three planners | Table: rebuilds per run, median / 95th / 99th percentile / slowest rebuild, rebuilds over 100 ms per 10,000, Dijkstra share of rebuild time, robots stopped |
| `ablation_event_route` | Supporting: event-route ablation | Run outcomes: event vs full-path recalculation | Full-path also rebuilds when a later segment is blocked (DEC-010 ablation). Result: up to 2.1× the replans and fewer finishes, no safety gain |
| `table_event_route` | Policy Comparison + supporting full-path set | Event vs full-path vs cycle replanning for three planners | Table; includes median rebuild time and splits unfinished runs into replan >100 ms (computing time, machine-dependent) and no route for 1000 ms (blocked). Rows show the change from event, shaded red where worse and blue where better (compute and median only beyond 20 %) |
| `evidence_horizon_150` | Supporting: horizon 150 ms check | Run outcomes vs horizon, including 150 ms | Optional, not run for the paper. Why the sweep stops at 100 ms (DEC-020) |
| `evidence_no_route_limit` | Supporting: no-route 500 ms check | Run outcomes: 500 ms vs 1000 ms no-route limit | Optional, not run for the paper. Why the limit is 1000 ms (DEC-019 amendment) |

Supporting figures are drawn only when their result set exists under
`../supporting/<set>/`. For the paper only `event-route-ablation` was run, so
`evidence_horizon_150` and `evidence_no_route_limit` are not generated (see
`../../README.md`). The full-path numbers are also in
`../tables/event_route_ablation.md`.
